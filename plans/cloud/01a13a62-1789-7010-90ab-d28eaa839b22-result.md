## Decisions

- **Fixture packages.** `test/site/package.json` lists the six plugins as `dependencies` (same ranges as the root's peers, guarded by a test) only so core discovers them; core `import()`s them by bare name from its own location, so they resolve through the repo root's `node_modules`. No install in `test/site`, no second lockfile, no extra CI step, no Dependabot entry for `/test/site`.
- **Builds in a temporary mirror.** Tests copy `test/site` to `<tmp>/test/site` and symlink `views/`, `assets/`, `config/`, `package.json` and `node_modules/` into `<tmp>`, so `theme: ../..` resolves unchanged and the fixture is never edited. Four variants (default; overrides = accent `#006400` + a `}` token + foreign `extra_css` + `home_posts: 2`; no plugins; `base_path: /sub`) are built once each in vitest's `globalSetup` and shared via `provide`/`inject`.
- **No top-level names but the helpers.** Pug inlines a page and all its includes into one function, so a theme `const lang` clashed with plugin-tags' `tag-overview.pug` (`const lang`) and failed every tag page. The theme therefore declares only the six §S2.2 helpers at top level plus one object `themeBlog` (internal, not contract, said so in the README) that holds the post selection, archive grouping, `extra_css`/`footer_links` resolution and the language switch. Views call `pageLang({ meta })` where the spec's prose says `lang`.
- **Dates in UTC.** `formatDate` passes `timeZone: 'UTC'` to `toLocaleDateString`, and `isoDate`/the archive year use UTC: a YAML `date` is midnight UTC, so a build west of UTC would otherwise print the previous day.
- **Token names guarded too.** `tokens.pug` follows the normative code (value check, `_`→`-` in the name only) and additionally drops a group or token whose *name* is not `[A-Za-z0-9_-]+`, since a YAML key with `}` would break out of the rule just like a value.
- **`extra_css` rejects `/\…`** as well as `//…`: browsers read `/\host/x.css` as protocol-relative.
- **`homeHref`/rule 2 of §S2.8 require a `layout`**, like rule 1: a home page without one is not rendered, so linking it would 404. Ties on `dirname` length and on duplicate slugs are broken by `href`.
- **Empty legal nav omitted.** With no `footer_links` for the page's language the footer renders no `nav.site-footer__legal` (an empty labelled landmark helps nobody).
- **Archive skips posts whose date does not parse** (no year to group by); they still appear on the home.
- **`--nera-code-*` mapping on `.nera-code-scope, .nera-code`**: the extra selector makes plain fenced blocks inside the post body (which plugin-code-blocks styles with the same properties on `.nera-code-scope pre`) use the theme's colours instead of the plugin's white.
- **Fixture `copy_button: false`** in `config/code-blocks.yaml`: the site ships no script, so the button would stay `hidden`; the README names both options.
- **Fixture vendor copies** come from each plugin's own publish bin; `fontawesome-cdn-link.pug` (published along by plugin-social-media-links' bin) was deleted from the fixture so it cannot be included by mistake.
- **plugin-tags `group_by_lang: true`** in the fixture, so German tag pages live under `/de/tags/` with `lang: de`; recommended in the README for multilingual sites.
- **`validate.yaml` promotes all 21 output rules to `error`** (stricter than "on"): any finding also flips `ok` to false. Legal paths are configured explicitly per language.
- **YAML in tests** comes from core's own `yaml` dependency (resolved from `@nera-static/core`'s location), so no extra devDependency is needed and the tests parse exactly as the build does.
- **Plugin classes are read from `node_modules`**, which hold the npm tarball's `files`; installed versions equal the floors except navigation, where the lockfile resolves 3.1.1 for `^3.1.0` (no class changes); the test accepts `3.1.x` for it.
- **vitest `isolate: false`**: the test files only read the shared builds.

## Review hints

- **Visual**: I checked screenshots in headless Chromium only (desktop 1100 px, mobile 375 px, keyboard focus). Not checked: Safari/Firefox, `prefers-reduced-motion`, 200 % zoom, a long post title in the header, RTL. The prev/next arrows use `content: '←' / ''` (alt text so screen readers skip them), with a plain `content` fallback before it for older browsers.
- **The "Quiet paper" judgement** (sizes, spacing, uppercase "Recent posts" label, the date above the title via flex `order`) is mine; the DOM order stays media → title → date → excerpt as §S4.1a lists it.
- **`themeBlog`** is a new top-level name in every page's Pug scope; a site template declaring `const themeBlog` would clash. Unlikely, but it is the price of the shared-scope rule above.
- The Tokens test compares the beautified `<style>` (`--theme-color-accent: #8c3a12;`, with a space core's js-beautify adds), not the raw `:root{…}` string the template emits.
- `npm pack` in `package.test.js` runs `npm` from `PATH`; it needs no network.
- The CHANGELOG uses four-space bullets as the fleet format says; GitHub renders them as a code block.
